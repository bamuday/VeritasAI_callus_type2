# VeritasAI — Database Setup

This document explains the PostgreSQL database, SQLAlchemy models, Alembic migrations, and local database operations.

---

# 1. Database Stack

VeritasAI uses:

```text
PostgreSQL 16
SQLAlchemy
Psycopg
Alembic
```

Architecture:

```text
FastAPI
   │
   ▼
SQLAlchemy
   │
   ▼
Psycopg
   │
   ▼
PostgreSQL
```

# 5. Database Models

Main entities:

```text
User
AuthAccount
Essay
Analysis
SentenceAnalysis
```

Relationships:

```text
User
 ├── AuthAccount
 └── Essay
       └── Analysis
             └── SentenceAnalysis
```

---

# 6. Users

Stores application users.

Typical fields include:

```text
id
name
email
password_hash
avatar_url
created_at
updated_at
```

Email should be unique.

---

# 7. Auth Accounts

Stores external identity mappings.

Conceptually:

```text
provider
provider_account_id
user_id
created_at
```

Examples:

```text
google + Google account ID
github + GitHub account ID
```

---

# 8. Essays

Stores saved user essays.

Conceptually:

```text
id
user_id
title
content
word_count
created_at
updated_at
```

---

# 9. Analyses

Stores an analysis snapshot.

Conceptually:

```text
id
essay_id
detector_version
overall_score
flag_level
explanation
result_json
created_at
```

The JSON snapshot makes it possible to preserve the analysis result associated with a particular essay.

---

# 10. Sentence Analyses

Stores sentence-level analysis.

Conceptually:

```text
text
flag_level
signal_score
passage_category
explanation
signals_json
created_at
```

---

# 11. Cascade Behavior

The relationships are designed so that:

```text
Delete User
   ↓
Delete Essays
   ↓
Delete Analyses
   ↓
Delete Sentence Analyses
```

and:

```text
Delete Essay
   ↓
Delete Analyses
   ↓
Delete Sentence Analyses
```

Use this carefully in production.

---

# 12. Run Migrations

From backend:

```bash
cd backend
source .venv/bin/activate
alembic upgrade head
```

Check current revision:

```bash
alembic current
```

---

# 13. Create a Migration

After modifying SQLAlchemy models:

```bash
alembic revision --autogenerate -m "describe schema change"
```

Review the generated migration manually.

Then:

```bash
alembic upgrade head
```

Do not blindly trust autogenerated migrations.

---

# 14. Migration History

Current migration structure:

```text
0001_initial.py
0002_credentials.py
```

The migration chain should remain linear.

Check:

```bash
alembic history
```

---

# 15. Rollback

To move back one migration:

```bash
alembic downgrade -1
```

Check:

```bash
alembic current
```

Do not run production rollbacks without understanding the migration's data impact.

---

# 16. Reset Local Database

Warning: this deletes local database data.

```bash
docker compose down -v
docker compose up -d postgres
```

Then:

```bash
cd backend
source .venv/bin/activate
alembic upgrade head
```

---

# 18. Production Database Rules

Do not use:

```text
veritasai / veritasai
```

in production.

Use:

- Strong database password
- Private network
- TLS where appropriate
- Backups
- Least-privilege database user
- Monitoring
- Connection limits
- Disaster recovery plan

Never commit production database credentials.
